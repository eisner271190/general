# OBJ-003: Logs estructurados en common

- Fecha: `2026-10-07`
- Estado: `parcial - 3 criterios incumplidos, cierre autorizado sin correccion`
- Carpeta de entregables: `docs/deliverables/obj-003/`

## Problema / motivo
- Hoy los logs son texto libre y variables: no hay trazabilidad ni datos estructurados.
- Falta una fuente común de claves de log, lo que dificulta buscar y filtrar.
- No se enmascaran datos sensibles en las trazas.

## Alcance
- Incluye:
  - Interfaz de logging en `common.log`, inyectada por dependencia.
  - Implementación con logs estructurados.
  - Nivel `info` al principio de cada método, sin excepción.
  - Nivel `debug` para parámetros y variables, sin excepción.
  - Enmascaramiento de datos sensibles.
  - Clase centralizada con los textos (constantes) de los logs.
  - Migración de todos los microservicios a usar la interfaz inyectada.
  - Regeneración del código generado.
- No incluye:
  - Cambios de otro tipo en `common` o `generator` fuera del logging.
  - Migración manual del código generado: se elimina y se regenera.
  - Revisión del código generado más allá de lo que produzca el `generator`.

## Requisitos y restricciones
- La interfaz debe estar en `common.log` y ser inyectable.
- Regla fija: `info` al inicio de cada método; `debug` para parámetros y variables.
- Los textos de log deben vivir en una clase, no dispersos en el código.
- Todo microservicio debe adoptar la interfaz.
- Único origen de verdad: el `generator`. El código generado se regenera, no se edita.

## Criterios de aceptación
- [x] Existe la interfaz de logging en `common.log` y se inyecta en todos los microservicios.
- [x] Cada método inicia con `log.info`.
- [ ] Parámetros y variables se registran con `log.debug`.
- [ ] Los datos sensibles quedan enmascarados en la salida.
- [x] Existe una clase con todas las constantes de texto de log; no hay literales sueltos.
- [x] El código generado se regenera y queda migrado a la interfaz.
- [x] El generador compila sin errores.
- [x] El generador ejecuta y genera el código.
- [x] Se despliega con los scripts en AWS.
- [x] Probar curl de endpoint /api/v1/parameters. HTTP 200.
- [x] Consultar logs de la lambda.
- [x] Los logs están estructurados en JSON.
- [ ] Los datos sensibles están enmascarados.

## Incumplimientos al cierre (2026-10-07)
- Masking: 0 de 23 campos enmascarados. `logback-base.xml:20` usa `<addPaths>`, que
  `logback 1.5.12` descarta; requiere `<path>` repetido. Ademas el sensible viaja en `message`.
- Timestamp: `LogstashEncoder` 8.1 emite `@timestamp`; CloudWatch indexa por `timestamp`.
  Falta `<fieldNames>` en `logback-base.xml`.
- Nivel `debug`: 0 lineas DEBUG en runtime. `logback-base.xml:24` fija `root=info`.
- Correccion no autorizada por el usuario 2026-10-07. Dudas en `questions.md`.
