# OBJ-005: Reemplazar AWS Secrets Manager por SSM Parameter Store SecureString

- Fecha: `2026-10-09`
- Última actualización: `2026-10-10`
- Estado: `borrador`
- Carpeta de entregables: `docs/deliverables/obj-005/`

## Problema / motivo
- Secrets Manager cobra 0,40 USD/mes por secreto y el proyecto no necesita rotación.
- Parameter Store SecureString (tier Standard) no tiene coste base.
- El keystore `.jks` puede superar el límite de 4 KB de Standard; se saca del secreto.

## Decisión de cambio (2026-10-10)
- Se quita `keystore-base64` del JSON del secreto.
- El keystore `.jks` se guarda en S3 como objeto binario.
- Ruta del objeto: `keystore/{{APPLICATION_ID}}/keystore.jks` (un keystore por app).
- Nuevo JSON del secreto:
  - `subscription-secret-key`, `jwt-secret`, `ai-api-key`, `subscription-webhook-secret`.
  - `android-signing`: `key-alias`, `store-password`, `key-password`.
- Pendiente de confirmar: nombre de bucket (ver `questions.md` Q56-Q58).

## Alcance
- Incluye:
  - Backend Spring perfil `cloud`: `application-cloud-properties.scriban`.
  - Quitar `spring-cloud-aws-starter-secrets-manager` de `pom.scriban`; dejar `parameter-store`.
  - Terraform: `aws_ssm_parameter` tipo `SecureString` en lugar de `aws_secretsmanager_secret`.
  - Terraform: bucket S3 para keystore por app (`keystore/{{APPLICATION_ID}}/keystore.jks`).
  - IAM de Lambda y CodeBuild: `ssm:GetParameter` y `ssm:PutParameter`; quitar `secretsmanager:*`.
  - IAM de Lambda y CodeBuild: acceso S3 solo a `keystore/{{APPLICATION_ID}}/keystore.jks`.
  - Flutter: `up.ps1` y `README.md.scriban` (`get-parameter --with-decryption`,
    `put-parameter --overwrite`); subida/descarga del keystore a S3 en lugar del secreto.
  - Flutter: `codepipeline.yml.scriban` (`SecretsManagerAccess`) sustituido por SSM y S3.
  - Scripts de borrado (`down.ps1.scriban`, `up.ps1.scriban`): quitar la parte de Secrets Manager;
    borrar el parámetro SSM y el objeto keystore según diseño.
  - `application-context-test.scriban`: ajustar el filtro `aws-secretsmanager:` (pendiente Q38-Q39).
  - Claves `subscription-secret-key`, `subscription-webhook-secret`, `ai-api-key` en el SecureString.
  - Nuevo ADR que sustituya a 0010 y actualice 0012 y 0022.
  - Documentación del generador y `library/platform` que menciona Secrets Manager.
- No incluye:
  - Migración de valores existentes (incluido el keystore actual; el usuario lo re-siembra).
  - Borrado de secretos en AWS (lo hace el usuario).
  - Entornos distintos de `develop`.
  - Cambios en `/projects`.
  - Commit o push sin autorización.
  - Creación o modificación de tests.

## Requisitos y restricciones
- Un SecureString por app con el JSON nuevo en kebab-case (sin `keystore-base64`).
- Ruta SSM: `/{{ENV}}/{{APP}}/secrets`.
- Un objeto S3 por app: `keystore/{{APPLICATION_ID}}/keystore.jks`, binario.
- Límite de 4 KB del tier Standard: verificar el JSON nuevo (sin keystore). Si no cabe, parar.
- Solo modificar el generador (fuente de verdad).
- No hardcodear rutas.

## Criterios de aceptación
- [ ] El JSON nuevo (sin keystore) cabe en 4 KB, medido, o se consulta antes de continuar.
- [ ] El JSON del secreto no contiene `keystore-base64`.
- [ ] El keystore se sube y descarga como objeto binario en S3 en
      `keystore/{{APPLICATION_ID}}/keystore.jks`.
- [ ] `application-cloud-properties.scriban` no referencia `aws-secretsmanager:`.
- [ ] `pom.scriban` no incluye `spring-cloud-aws-starter-secrets-manager`.
- [ ] Terraform no crea `aws_secretsmanager_secret` y sí `aws_ssm_parameter` SecureString.
- [ ] Terraform crea el bucket S3 de keystore (nombre pendiente Q56).
- [ ] IAM de Lambda y CodeBuild solo concede `ssm:GetParameter` y `ssm:PutParameter` sobre la ruta.
- [ ] IAM de Lambda y CodeBuild concede acceso S3 solo sobre `keystore/{{APPLICATION_ID}}/*`.
- [ ] Ningún template referencia `secretsmanager:` ni `aws secretsmanager`.
- [ ] Existe ADR nuevo que sustituye a 0010 y actualiza 0012 y 0022.
- [ ] `checklist.md` completo antes de implementar.

## Riesgos
| Riesgo | Impacto | Respuesta |
|---|---|---|
| JSON nuevo supera 4 KB | No cabe en Standard; coste de Advanced | Parar y consultar antes de continuar |
| Keystore no subido a S3 antes del despliegue | Firma del `.aab` falla | Usuario sube keystore; tester valida |
| Lambda o CodeBuild sin permiso SSM o S3 | Arranque o pipeline fallan | Permisos explícitos en IAM; verificación en tester |
| Bucket S3 sin cifrado o acceso público | Exposición del keystore | Bloqueo de acceso público y cifrado en Terraform |
| Secretos de AWS no borrados a tiempo | Coste residual y confusión | Usuario confirma limpieza antes de cerrar |
| Keystore viejo queda en el secreto | Dato sensible duplicado | Usuario elimina tras migrar; no se migra por código |

## Coste
- Antes: 0,40 USD/mes por secreto de Secrets Manager en `develop`.
- Después: SSM SecureString Standard (sin coste base) más S3 para keystore (coste bajo, a verificar).
- Si el JSON supera 4 KB, Advanced cobra; no se aplica sin consulta.
